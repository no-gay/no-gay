#### 4.2 Выполненные работы по сопровождению

**Работа 1: Исправление ошибки аутентификации**
- **Описание:** Пользователи не могли войти в систему при использовании VPN
- **Причина:** Проблема с IP белтингом в проверке безопасности
- **Решение:** Модифицирован алгоритм валидации IP адресов с учетом proxy серверов
- **Результат:** Ошибка устранена, пользователи смогли авторизоваться
- **Время на исправление:** 2 часа

**Работа 2: Оптимизация запроса к базе данных**
- **Описание:** Страница с отчетом загружалась 15 секунд
- **Анализ:** Запрос был выполнен без оптимизации, N+1 problem
- **Решение:** 
  - Добавлены индексы на часто используемые поля
  - Реализовано объединение таблиц (JOIN вместо отдельных запросов)
  - Применено кэширование результатов
- **Результат:** Время загрузки снизилось до 1.5 секунд (в 10 раз быстрее)
- **Время на оптимизацию:** 4 часа

**Работа 3: Обновление Django с версии 3.2 на 4.0**
- **Описание:** Необходимо было обновить фреймворк для получения новых функций и исправлений безопасности
- **Этапы:**
  - Изучение документации по миграции
  - Запуск тестов совместимости
  - Обновление зависимостей в requirements.txt
  - Фиксирование несовместимого кода
  - Запуск полного набора unit тестов
  - Тестирование на staging сервере
  - Развертывание в production
- **Результат:** Система успешно работает с новой версией Django
- **Время на обновление:** 8 часов

**Работа 4: Установка и настройка системы мониторинга**
- **Описание:** Настроена система DataDog для мониторинга приложения
- **Реализовано:**

### 5. Работа с документами отраслевой направленности

#### 5.1 Изученные типы документации

**Техническое задание (ТЗ):**
- **Назначение:** Описание требований к разрабатываемому функционалу
- **Структура:**
  - Описание функциональности
  - Список требований (функциональные и нефункциональные)
  - Критерии приемки
  - Сроки разработки
  - Ограничения и особенности
- **Пример:** ТЗ на разработку модуля управления пользователями (30 страниц)

**Спецификация требований (SRS – Software Requirements Specification):**
- **Назначение:** Подробное описание что должно быть разработано
- **Содержит:**
  - Описание бизнес-процессов
  - Функциональные требования
  - Нефункциональные требования (производительность, безопасность)
  - Use case диаграммы
  - Экраны и макеты интерфейса
  - Процессы обработки ошибок

**Архитектурная документация:**
- **Назначение:** Описание высокоуровневой структуры системы
- **Документы:**
  - Диаграммы компонентов системы
  - Диаграммы развертывания (deployment diagrams)
  - Описание взаимодействия модулей
  - Стек технологий и обоснование выбора
  - Описание слоев приложения (presentation, business logic, data access)

**API документация (OpenAPI/Swagger):**
- **Назначение:** Описание API endpoints для интеграции
- **Содержит:**
  - Описание всех endpoint'ов
  - Методы запроса (GET, POST, PUT, DELETE)
  - Параметры запроса и ответа
  - Примеры вызовов и ответов
  - Коды ошибок и их описание
  - Аутентификация и авторизация
- **Инструмент:** Swagger UI для интерактивного тестирования

**Р��ководство пользователя:**
- **Назначение:** Инструкции для конечных пользователей
- **Содержит:**
  - Описание функций системы
  - Пошаговые инструкции
  - Снимки экранов с пояснениями
  - FAQ (часто задаваемые вопросы)
  - Контакты поддержки

**Руководство администратора:**
- **Назначение:** Инструкции для системных администраторов
- **Содержит:**
  - Установка и настройка системы
  - Резервное копирование и восстановление
  - Управление пользователями и правами доступа
  - Мониторинг и диагностика
  - Процедуры восстановления при сбоях

**Акты приемки и тестирования:**
- **Назначение:** Документирование завершения работ
- **Содержит:**
  - Дата и время тестирования
  - Результаты проверки функциональности
  - Список обнаруженных ошибок
  - По��писи разработчика и заказчика

**Стандарты документирования (ГОСТ, ЕСКД):**

  - Единообразный формат

**Работа 3: Оптимизация запросов**
- Проанализированы медленные запросы (query log)

  - Запрос с выборкой всех заказов — 8 секунд
  - Запрос аналитики по продажам — 12 секунд
- Оптимизация:
  ```sql
  -- ДО: медленный запрос без индекса
  SELECT * FROM orders WHERE user_id = 123 AND created_at > '2024-01-01';
  
  -- ПОСЛЕ: с индексом и оптимизацией
  CREATE INDEX idx_orders_user_created ON orders(user_id, created_at);
  SELECT id, total, status FROM orders 
  WHERE user_id = 123 AND created_at > '2024-01-01'
  ORDER BY created_at DESC;
  ```
- Результат: запросы ускорены в 10 раз

  - Скорость выполнения запросов

**Работа 5: Управление пользователями и правами доступа**
- Созданы роли (roles) для разных функций:
  ```sql
  CREATE ROLE developer WITH LOGIN PASSWORD 'secure_pwd';
  CREATE ROLE analyst WITH LOGIN PASSWORD 'secure_pwd';
  CREATE ROLE readonly WITH NOLOGIN;
  ```
- Настроены права доступа:
  ```sql
  -- Разработчик может читать и писать данные
  GRANT CONNECT ON DATABASE ecommerce_db TO developer;
  GRANT USAGE ON SCHEMA public TO developer;
  GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO developer;
  
  -- Аналитик может только читать
  GRANT CONNECT ON DATABASE ecommerce_db TO analyst;
  GRANT SELECT ON ALL TABLES IN SCHEMA public TO analyst;
  ```
- Все изменения логируются в audit таблице

#### 6.3 Освоенные команды и инструменты

**Основные SQL команды:**
```sql
-- Создание таблицы
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    username VARCHAR(50) NOT NULL UNIQUE,
    email VARCHAR(100) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Создание индекса
CREATE INDEX idx_users_email ON users(email);

-- Просмотр структуры таблицы
\d users

-- Вставка данных
INSERT INTO users (username, email) VALUES ('john_doe', 'john@example.com');

-- Обновление данных
UPDATE users SET email = 'newemail@example.com' WHERE username = 'john_doe';

-- Удаление данных
DELETE FROM users WHERE id = 1;

-- Выборка с фильтром и сортировкой
SELECT * FROM users WHERE created_at > '2024-01-01' ORDER BY username;

-- Объединение таблиц
SELECT u.username, COUNT(o.id) as order_count
FROM users u
LEFT JOIN orders o ON u.id = o.user_id
GROUP BY u.username
HAVING COUNT(o.id) > 0
ORDER BY order_count DESC;
```

**Команды psql:**
- `\l` — список баз данных
- `\d` — список таблиц
- `\d table_name` — структура таблицы
- `\du` — список пользователей и ролей
- `\i file.sql` — выполнение SQL файла
- `\copy` — импорт/экспорт данных

**Инструменты мониторинга:**
- `pg_stat_statements` — просмотр статистики запросов
- `EXPLAIN ANALYZE` — анализ плана выполнения запроса
- `SELECT * FROM pg_stat_activity` — активные соединения
- DataDog — полнофункциональный мониторинг

#### 7.3 Применяемые принципы UX/UI дизайна

**1. User-Centered Design (дизайн, ориентированный на пользователя)**
- Регулярные интервью с целевой аудиторией
- Persona разработка (5 основных типов пользователей)
- User journey mapping (путь пользователя через приложение)
- Тестирование дизайна с реальными пользователями (user testing)

**2. Визуальная иерархия**
- Размер элементов привлекает внимание (большие элементы важнее)
- Цвет используется для выделения ключевых элементов
- Белое пространство (spacing) помогает структурировать информацию
- Контраст между элементами улучшает читаемость

**3. Konsistency (Постоянство/Консистентность)**
- Единые стили кнопок, форм, текста во всем приложении
- Использование одной цветовой палитры
- Одинаковые иконки для одинаковых функций
- Стандартное расположение навигационных элементов

**4. Feedback (Обратная связь)**
- Кнопки меняют вид при нажатии (visual feedback)
- Сообщения об успешном/неуспешном действии
- Прогресс-бары для длительных операций
- Анимация для привлечения внимания к изменениям

**5. Responsive Design (Адаптивный дизайн)**
- Мобильный дизайн (320px - 480px)
- Планшет (768px - 1024px)
- Десктоп (1920px+)
- Тестирование на реальных устройствах

**6. Accessibility (Доступность)**
- Цветовой контраст соответствует стандартам WCAG
- Размер шрифта не менее 14px
- Поддержка навигации с клавиатуры
- Поддержка screen readers для слабовидящих
- Альтернативный текст для изображений

**7. Performance (Производительность)**
- Оптимизация размера изображений (compression)
- Ленивая загрузка (lazy loading) для улучшения скорости
- SVG вместо PNG для иконок (меньше размер)
